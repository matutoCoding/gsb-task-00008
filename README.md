# 岸桥–集卡协同作业估算页面

把多条作业线的岸桥速度、集卡数量、两边堆场放进同一张排队网络里做蒙特卡洛离散事件仿真，
解决“车与岸桥互相等、调一个数另一边就变、抽车会连带拖慢别的线”的估算问题。

## 打开

直接用浏览器打开 `index.html`（纯静态，无需服务器、无外部依赖）。
也可以 `python3 -m http.server` 后访问对应地址。

## 文件

- `index.html` — 页面结构
- `app/style.css` — 样式
- `app/sim.js` — 离散事件仿真引擎（岸桥装船→运输→堆场卸箱→空车返回的闭合循环）
- `app/charts.js` — 轻量 Canvas 图表
- `app/app.js` — 状态、方案评估、交互、本地持久化

## 功能对照

1. **设定每条线的岸桥速度与集卡数，估进度**：线卡片直接改数字，40 次随机仿真给出每线/全网完工的中位与 80% 区间。
2. **车不够，标出哪条线先停**：“岸桥等车”比例（饥饿率）最高的线上顶部 KPI 与卡片红标。
3. **车太多，看岸边等待与堆场拥堵**：岸边每箱等待分钟、岸前车数曲线；堆场利用率、在场车数、等待/箱。
4. **岸桥故障分车**：故障后自动给出 3 个分流方案（贪心保吞吐 / 平均摊 / 集中补最缺车线），每个方案显示各线变慢程度与全网完工，点卡片采用并重算。
5. **集卡下班 / 车辆数变化**：输入新的在网车总数，给出“损失最小撤车 / 均衡缩减”（加车时为增益最大 / 平均）方案，进度自动重估。
6. **天气 / 视线不好**：顶部下拉整体下调岸桥有效速度，并温和放大运输时间。
7. **临时加线**：设新线参数后，从现有线抽车给出 3 个方案，显示每条被抽线的拖慢与全网账。
8. **关闭页面再回来**：全部条件、故障、修正系数、天气、上次结果存 `localStorage`，再打开直接恢复。
9. **实际对不上时修正后续估算**：“填报实际进度”按 实际完成 ÷ 同期估算应完成 折成岸桥速度修正系数（0.4–1.8），并更新真实剩余箱；从当前状态往后算，不从头重来。车数/堆场布局变化后旧系数自动标记失效。

## 关键设计原则

- **任何条件改动 → 结果立即标记过期**（顶部黄条），旧结论作废，点“重新估算”后才出现新数。
- **所有方案都是全网仿真**：共享堆场的互相挤占、岸边排队堆积都计入，不做单线孤立估算。
- 方案分配用“每多/少一台车的全网边际吞吐”贪心搜索，配合观察窗内吞吐量评估。
