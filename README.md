# 岸桥—集卡联动估算台

一个零依赖的静态页面，用来联动查看岸桥速度、集卡数量、岸边等待和两侧堆场拥堵。

## 使用方式

在当前目录启动任意静态服务器：

```bash
python3 -m http.server 8000
```

然后打开 `http://localhost:8000/index.html`。也可以直接双击 `index.html` 打开。

## 已覆盖的场景

- 设置每条作业线的岸桥速度、分配集卡、剩余箱量、已完成箱量和目标堆场。
- 自动估算当前速度、车辆匹配率、饱和配车数、剩余时间和未来时段进度。
- 集卡不足时，按断供风险标出预计最先停摆的作业线。
- 集卡过多时，计算岸边平均等待、排队车辆和堆场入口等待。
- 岸桥故障后扣留原车并提供三套分流方案，执行前可看到总速度和工时变化。
- 下班导致在港集卡减少时，提供三套收缩方案并重估全部线。
- 天气或视线系数会整体乘到每条岸桥效率上。
- 临时加线时，先使用空闲车，再提供三套抽车方案。
- 实际进度与估算不符时，用一段时间的实际箱量修正后续效率，不清空已完成进度。
- 所有条件保存在浏览器 `localStorage`，关闭页面后再打开会自动恢复。

## 模型口径

- 岸桥理论速度 × 天气系数 × 历史修正系数，得到该线理论能力。
- 集卡可持续供给为 `车辆数 × 60 ÷ 单车往返分钟`。
- 单车往返分钟由基础往返、堆场入口排队等待、堆存占用附加等待共同决定。
- 两侧堆场共享服务能力；某侧各线需求超过堆场能力时，超过部分转为排队，再反向拉长该侧车辆周期。
- 页面使用固定点迭代，让“堆场排队 → 车辆周期 → 岸桥速度 → 堆场到达量”同时收敛。
- 任何输入变化、方案执行或故障切换都会重新运行整套模型，不沿用旧结论。

该模型用于调度前的快速估算，不替代码头 TOS 的实时微观仿真。
